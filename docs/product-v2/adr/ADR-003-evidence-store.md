# ADR-003 — производный слой документов, evidence и фактов

Статус: принято и реализовано в Stage 04 (`apps/rag-api/src/evidence/`).

## Контекст

Stage 01 показал: чанки индекса не годятся как единица доказательства. В чанке может оказаться несколько разделов договора, несколько листов сметы или граница страниц. Метаданные чанка берутся от последнего заголовка, поэтому цитата указывает не на тот раздел или лист. Кроме того, индекс не знает, что дополнительное соглашение меняет пункт договора.

## Решение

- **Хранилище.** Отдельная `state/evidence.sqlite`, производная от индекса. Пересборка источника заменяет все его строки: `npm run evidence:build`, `POST /api/evidence/rebuild`, фоновая пересборка после индексации через API. Откат — удалить файл и пересобрать.
- **Документ** (`DocumentRecord`). Один на индексированный файл: вид (договор, ДС, приложение, смета, акт, письмо, прочее), номер, дата, ссылка на родительский договор, хеш содержимого. Хранится только имя файла, без абсолютного пути.
- **Фрагмент-доказательство** (`EvidenceSpan`). Абзац или строка таблицы из markdown-кэша конвертера. Раздел, страница, лист и строка у каждого свои. Стабильный id вычисляется из документа, позиции и хеша текста. Ссылка на чанк индекса нужна для превью. Front matter конвертера, где лежит абсолютный путь, отрезается.
- **Факт** (`StructuredFact`). Детерминированные правила `rules/1`: стороны, цена, НДС, аванс и его срок, гарантийное удержание и срок его возврата, гарантийный срок, даты работ, неустойка, итог сметы. Нормализованное значение, сырой текст, условие, пункт договора. Факт без ссылки на фрагмент не сохраняется.
- **Граф редакций:**
  - ДС связывается с договором из того же источника по номеру и дате. Если договор не найден или совпадений несколько, связь `unknown`.
  - Пункт «N изложить в новой редакции» из датированного ДС заменяет факт того же типа и пункта. Если пункт не указан, замена идёт только при единственном кандидате.
  - Заменённый факт не удаляется: он получает `superseded`, `valid_to` и ссылку на новый.
  - Разные значения без установленного приоритета помечаются `conflict`, в том числе цена договора против итога сметы.

## Последствия

- Цепочка «факт → фрагмент → превью точного места» доступна через `GET /api/evidence/facts/:id/trace`.
- Поиск (Stage 06) и проверка ответов (Stage 07) смогут опираться на фрагменты и факты. Индекс и retrieval на этом этапе не меняются.
- Индексация ежедневным агентом не пересобирает evidence автоматически: нужен `npm run evidence:build -- --all`.
- Правила извлечения покрывают стартовый набор условий договора, а не все виды РД.
