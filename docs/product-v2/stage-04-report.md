## Revision 1 — после независимой проверки (verdict FAIL)

Подтверждено проверкой: все gates PASS (`npm test` 345/345, контракты chat/conversation/evidence PASS и завершаются сами), trace до страницы/листа/строки, замена п. 3.1 и 4.2, сохранение устаревших фактов, отклонение фактов без evidence, неизвестный родитель / недатированное ДС / ДС без номера пункта → conflict, идемпотентность, сбой evidence-БД не валит индексацию. Не подтверждено — три adversarial-случая.

### Findings
1. **Срок чужого обязательства становился сроком аванса.** «Аванс в размере 3%. Подрядчик передает отчет в течение 30 календарных дней…» давал `advance_term=30`.
   - Причина: срок искался по всему абзацу.
   - Исправление: срок аванса, срок возврата удержания и предел неустойки читаются только из предложения, где задано само обязательство (`sentenceMatching` в `fact-extractor.js`).
2. **ДС заменяло факт из явно другого пункта.** «Пункт 9.9 … аванс 10%» заменял базовый п. 3.1.
   - Причина: единственный кандидат заменялся без сверки номеров пунктов.
   - Исправление (`version-graph.js`): факт с другим явно указанным пунктом не заменяется; без точного совпадения допускается только единственный кандидат с неизвестным номером пункта. Разные значения → `conflict`.
3. **Пути и секреты из тела документа сохранялись и возвращались API.** Заявление отчёта о privacy было шире реализации.
   - Исправление: `evidence-redaction.js` маскирует абсолютные пути (Windows, UNC, POSIX, `file://`) и похожие на секреты значения (`Bearer`, `api_key=`, `пароль:`, JWT, `sk-…`, приватные ключи, userinfo и токены в URL) до нарезки фрагментов и повторно при записи в хранилище (текст, заголовок, сырое значение, условие, нормализованные значения). Идемпотентно; обычный текст договора не меняется. Индекс и markdown-кэш не изменялись.

## Revision 2 — после повторной проверки (verdict FAIL)

Подтверждено: три дефекта Revision 1 закрыты, мутации регрессионных тестов вызывают падение, все gates PASS (`npm test` 353/353, контракты chat/conversation/evidence PASS). Найдены два новых дефекта маскировки.

### Findings
1. **`file:///` с пробелом в папке маскировался не полностью** (`file:///C:/Проект Альфа/акт.pdf.` -> `[path] Альфа/акт.pdf.`).
   - Причина: шаблон `file://` не использовал правило сегментов с пробелами, общее для путей Windows/UNC/POSIX.
   - Исправление: `file://` использует те же сегменты; результат `Путь [path].`
2. **Лишняя маскировка обычного текста** (`Пароль: не требуется.` -> `Пароль: [redacted] требуется.`).
   - Причина: любое значение после «пароль:»/`token=` считалось секретом.
   - Исправление: значения, которые сообщают об отсутствии секрета (слово целиком кириллицей, `none`, `not`, `n/a`, `required`, прочерк), не маскируются; у замаскированного значения сохраняется завершающая пунктуация.

### Регрессионные тесты
- `tests/evidence-redaction.test.mjs`: `file://` с пробелами (локальный и сетевой) маскируется целиком; фразы «Пароль: не требуется», «Password: not required», «api_key: none», «Токен: отсутствует; пароль — не задан» не меняются; `пароль: hunter2.` -> `пароль: [redacted].`, `Пароль: Секрет123` маскируется; идемпотентность на смешанной строке.

## Revision 4 — после повторной проверки (verdict FAIL)

Подтверждено: блокер Revision 3 закрыт, все gates PASS (`npm test` 357/357). Найдены утечки в правиле значений секретов и нечувствительный тест.

### Findings
1. **Многословный пароль маскировался частично** («Пароль: Красная Луна» → `[redacted] Луна`), **пароль в кавычках не маскировался вовсе**.
   - Причина: значением считался один токен без пробелов.
   - Исправление: значение читается до конца фразы (запятая, точка с запятой, конец предложения); отдельно разбираются значения в `"…"`, `'…'`, `«…»` — в том числе с запятой внутри.
2. **Отрицание после настоящего пароля отменяло маскировку** («Пароль: DemoPass42 не передавать третьим лицам.»).
   - Причина: проверялось любое отрицание после значения.
   - Исправление: значение сохраняется, только если вся фраза говорит об отсутствии секрета («не требуется», «нет», «отсутствует», «без пароля», `none`, `not required`, прочерк), допускается одно слово перед отрицанием («доступа не требуется»). Запрет передачи отсутствием не считается — значение маскируется вместе с остатком фразы.
3. **Тест «следующего слова» был нечувствителен к мутации**: ключи распознавались только латиницей, поэтому кириллический «Токен» не проверял нужную ветку.
   - Исправление: ключи «пароль» и «токен» распознаются; в тестах обе формы ключа и латинский `token: доступа не требуется`.

## Revision 6 — после повторной проверки по закрытому списку (verdict FAIL)

Подтверждено: находки Revision 5 закрыты, три мутации обнаруживаются, все gates PASS (`npm test` 364/364); 21 из 22 собственных примеров по закрытому списку прошли, идемпотентность соблюдена, новых ограничений вне списка нет.

### Finding
