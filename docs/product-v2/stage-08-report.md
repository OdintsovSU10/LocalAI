## Changed
- Новое приложение `apps/telegram-bot/` — тонкий адаптер, без своей RAG-логики:
  - `src/config.js` — токен и список разрешённых пользователей только из окружения; адрес портала обязан быть локальным (loopback); без токена или списка бот не стартует;
  - `src/telegram-api.js` — клиент Bot API на исходящем long polling: входящий порт не открывается, вебхук не используется; токен вырезается из любых сообщений об ошибках;
  - `src/local-api.js` — вызовы портала: `/api/chat`, `/api/conversations`, `/api/conversations/import`, `/api/sources`, `/api/settings`, `/api/health`; наружу отдаются только названия и статусы, без путей и ключей;
  - `src/sessions.js` — состояние чата: разговор, закреплённый проект, последние источники, текущий запрос; ограничитель частоты на пользователя;
  - `src/format.js` — сообщение ответа (текст, список источников по меткам цитат, строка статуса проверки), ограниченная выдержка фрагмента, безопасная разбивка длинных сообщений, клавиатуры;
  - `src/handlers.js` — команды `/new`, `/project`, `/sources`, `/status`, `/cancel`, `/help`, обычный вопрос, кнопки уточнения проекта и фрагментов;
  - `src/bot.js`, `src/index.js` — цикл опроса с отступами при ошибках и точка входа.
- `package.json` -> `tg:start`, `tg:check`, `tg:test`, `tg:contract`.
- `README.md` -> раздел о Telegram: настройка, команды, приватность.

## Architecture decisions
- **Адаптер, а не второй backend.** Ответ всегда идёт через `/api/chat` портала, то есть через planner → retrieval → пакет доказательств → проверку Stage 07. В боте нет ни поиска, ни промптов.
- **Исходящий polling.** Локальный компьютер не открывает порт наружу и не нуждается в белом IP. Вебхук не используется.
- **Один чат — один разговор.** Идентификатор `tg-<chatId>` импортируется в Conversation Service, поэтому после перезапуска бота разговор продолжается. `/new` архивирует старый разговор и создаёт новый.
- **Наружу уходит минимум.** Только текст ответа, метки цитат (файл, пункт, лист и строка или страница) и статус проверки. Абсолютных путей, ключей и полного документа в сообщениях нет; выдержка фрагмента ограничена 700 символами и доступна по кнопке, а не автоматически.
- **Незнакомец не узнаёт ничего.** Любое сообщение не из списка получает нейтральный отказ без названий проектов и признаков того, что за ботом.
- **Содержимое не логируется.** В консоль идут только количества, вид ошибки и обрезанный текст ошибки; токен вырезается.

## Acceptance (Prompt Pack Stage 08) -> доказательство
Сквозной сценарий в `apps/telegram-bot/tests/flow.contract.mjs` на реальном портале с фейковой LLM:
1. вопрос про «Сокольники» при двух похожих проектах -> кнопки-кандидаты;
2. выбор кнопкой -> исходный вопрос возобновляется для выбранного проекта;
3. ответ приходит проверенным, со ссылками `[1]` и списком источников;
4. кнопка «Фрагмент 1» -> ограниченная выдержка;
5. follow-up остаётся в том же разговоре;
6. `/new` сбрасывает разговор и закреплённый проект — проект снова уточняется;
7. чужой пользователь получает только «Доступ не настроен.»;
8. в сообщениях нет локальных путей.

Остальное — в `apps/telegram-bot/tests/`: список разрешённых, ограничитель частоты, отмена долгого запроса, команды, разбивка длинных сообщений, приватность `/help`.

## Security/privacy
- `TELEGRAM_BOT_TOKEN` и `TELEGRAM_ALLOWED_USER_IDS` — только из `.env`; в репозитории их нет, в логах тоже.
- Адрес портала обязан быть loopback: бот не может быть перенастроен на удалённый backend.
- Если у портала включён `RAG_AUTH_TOKEN`, бот использует его в заголовке; токен не печатается.
- Ограничение частоты по пользователю, отмена запроса, тайм-аут.
- `/help` прямо предупреждает: документы и индекс остаются локально, но вопрос и ответ идут через серверы Telegram.

## Known limitations
- Уведомления (окончание индексации, найденные расхождения) не реализованы — нужен отдельный источник событий, это Stage 09.
- Состояние чата (последние источники, выбранный проект) живёт в памяти процесса: после перезапуска бота разговор сохраняется, а кнопки «Фрагмент» из старых сообщений перестают работать.
- Групповые чаты не рассчитаны специально: allowlist проверяет пользователя, а не чат.
- Ответ идёт 30–60 секунд, всё это время виден индикатор «печатает».
- Длинный ответ разбивается на части; кнопки прикрепляются к последней.
